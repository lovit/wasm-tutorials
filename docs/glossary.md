# 용어 대응표

브라우저에서 파이썬을 돌리는 이야기에는 웹 쪽 용어와 파이썬 쪽 용어가 섞인다. 억지로 번역하면 검색도 안 되고 뜻도 흐려지므로 원어를 그대로 쓰되, 처음 보는 말이 무엇인지는 여기 적어 둔다.

## 런타임

| 용어 | 뜻 |
| --- | --- |
| **WebAssembly (WASM)** | 브라우저가 돌릴 수 있는 저수준 바이너리 명령어 형식. C, C++, Rust 같은 언어를 컴파일해 만든다. 자바스크립트를 대체하는 게 아니라 옆에서 함께 돈다 |
| **wasm32** | 포인터가 32비트인 WASM. 주소를 32비트로만 표현하므로 메모리가 최대 4GB 다. Pyodide 가 여기에 해당한다 |
| **선형 메모리** | WASM 이 쓰는 메모리. 커다란 바이트 배열 하나가 전부다. 파이썬 객체도 전부 이 안에 있다 |
| **Emscripten** | C/C++ 를 WASM 으로 컴파일해 주는 툴체인. 파일 읽기 같은 운영체제 기능을 자바스크립트로 흉내 내 주는 것까지가 이 도구의 일이다 |
| **Pyodide** | CPython 을 Emscripten 으로 빌드한 것. 여기에 자바스크립트와 오가는 다리와 패키지 배포까지 얹혀 있다 |
| **JSPI** | JavaScript Promise Integration. 동기 함수 안에서 비동기 작업을 기다릴 수 있게 해 주는 WASM 확장. 파이썬 쪽에서는 `pyodide.ffi.run_sync()` 로 쓴다 |

## 값을 주고받기

| 용어 | 뜻 |
| --- | --- |
| **FFI** | Foreign Function Interface. 다른 언어의 함수를 부르는 방법. 여기서는 파이썬과 자바스크립트 사이를 말한다 |
| **PyProxy** | 자바스크립트가 들고 있는 파이썬 객체 손잡이. 객체 자체가 아니라 WASM 메모리 안의 위치를 가리키는 표라서, 다 쓰면 `destroy()` 로 놓아 줘야 한다 |
| **JsProxy** | 반대 방향. 파이썬이 들고 있는 자바스크립트 객체 손잡이 |
| **`create_proxy()`** | 파이썬 함수를 자바스크립트 콜백으로 넘길 때 수명을 붙잡아 두는 함수. 이걸 안 쓰면 첫 호출이 끝나는 순간 프록시가 풀린다 |
| **`toJs()` / `to_py()`** | 손잡이를 넘기는 대신 값을 통째로 복사해 상대 쪽 자료형으로 바꾸는 것 |
| **`jsnull`** | 자바스크립트의 `null` 을 파이썬에서 나타내는 값. `undefined` 는 `None` 이 되므로 둘이 구별된다 |

## 파일과 저장

| 용어 | 뜻 |
| --- | --- |
| **MEMFS** | 메모리 위에 만든 가짜 파일시스템. Pyodide 의 기본값이다. 파이썬에서는 진짜 파일처럼 보이지만 새로고침하면 사라진다 |
| **IDBFS** | 브라우저의 IndexedDB 에 얹은 파일시스템. 새로고침해도 남는다. 다만 `FS.syncfs()` 를 직접 불러야 실제로 저장된다 |
| **NativeFS** | File System Access API 로 사용자의 진짜 폴더를 마운트하는 것. Chromium 계열에서만 된다 |

## 패키지

| 용어 | 뜻 |
| --- | --- |
| **wheel (`.whl`)** | 파이썬 패키지 배포 형식. 실체는 정해진 이름 규칙을 가진 zip 파일이다 |
| **순수 파이썬 wheel** | 파일 이름이 `-py3-none-any.whl` 로 끝나는 것. C 확장이 없어서 어느 환경에서나 돈다. Pyodide 에서도 그대로 설치된다 |
| **ABI 태그** | 그 wheel 이 어떤 실행 환경을 겨냥했는지 알려주는 표시. Pyodide 314 는 `pyemscripten_2026_0` 이다 |
| **micropip** | Pyodide 안에서 도는 패키지 설치 도구. PyPI 에서 순수 파이썬 wheel 을 받아 설치한다 |
| **락파일** | Pyodide 가 미리 빌드해 둔 패키지 목록과 의존 관계를 적어 둔 파일. `pyodide-lock.json` |
| **PEP 783** | 패키지 만드는 사람이 PyPI 에 Pyodide 용 wheel 을 직접 올릴 수 있게 한 제안. 예전에는 Pyodide 팀이 전부 직접 빌드했다 |

## 격리와 보안

| 용어 | 뜻 |
| --- | --- |
| **CORS** | 다른 출처의 자원을 가져올 때 상대 서버의 허락을 확인하는 규칙. 브라우저 파이썬이 아무 URL 이나 못 읽는 이유다 |
| **cross-origin isolation** | 문서를 다른 출처와 격리된 상태로 두는 것. `SharedArrayBuffer` 를 쓰려면 반드시 이 상태여야 한다 |
| **COOP / COEP** | cross-origin isolation 을 켜는 두 응답 헤더. `Cross-Origin-Opener-Policy` 와 `Cross-Origin-Embedder-Policy` |
| **`SharedArrayBuffer`** | 여러 스레드가 함께 보는 메모리. 실행 중인 파이썬을 중단시키는 데 쓴다 |
| **service worker** | 페이지와 네트워크 사이에 끼어드는 스크립트. GitHub Pages 처럼 헤더를 못 넣는 곳에서 COOP/COEP 를 대신 붙이는 데 쓸 수 있다 |
| **SRI** | Subresource Integrity. 받아 온 파일의 해시를 미리 적어 두고 대조하는 것. 아래에 적었듯 이 저장소는 쓸 수 없다 |

### 이 저장소가 지고 있는 신뢰

예제가 실행하는 파이썬 런타임은 jsDelivr 에서 온다. 즉 CDN 이 내려주는 것을 그대로 믿는다는 뜻이다. SRI 로 대조하면 좋겠지만 dynamic `import()` 에는 `integrity` 를 걸 수단이 없다. `<script integrity>` 로 바꿀 수도 없다. ES module 이라서다.

그래서 남는 것은 두 가지다. URL 에 버전을 고정해 두는 것(`v314.0.5`), 그리고 완전히 자립해야 한다면 Pyodide 배포본을 직접 호스팅하는 것. 후자는 저장소가 수백 MB 로 불어나므로 이 저장소는 택하지 않았다.
