# 12. 내 데이터가 밖으로 안 나간다

CSV 를 올려 pandas 로 분석한다. 그리고 "안 나갔다" 를 어떻게 확인할 수 있는지, 어디까지 확인되는지 본다.

![예제 화면. 위쪽 상자에 다 읽었다는 안내가 있다. 데이터 고르기 절에는 파일 고르기 칸과 인코딩 선택칸과 파일 없이 예제 데이터로 버튼이 있다. 이 페이지가 주고받은 것 표에는 부팅에 쓴 요청 17건에 13.20 MiB 를 받았고 분석하며 생긴 요청은 0건이며 관측 칸에 이 계측에 잡힌 요청은 없습니다 가 초록 글씨로 적혀 있다. 이 계측이 못 보는 것 절에는 일부러 몰래 보내 보기 버튼과, 응답을 읽지 않는 fetch 를 보냈는데 센 요청이 17건에서 17건으로 늘지 않았다는 결과가 있다. 맨 아래 분석 결과에는 열 타입 고유값 결측 네 열짜리 표와 숫자 열 요약, 부서 별로 세기, 처음 세 줄이 차례로 나온다.](screenshot.png)

> 이 문서의 측정값은 Chrome 151.0.7922.34 (headless, macOS) 에서 2026-08-24 에 Pyodide 314.0.5, pandas 3.0.2 로 잰 것이다.

## 무엇을 배우나

- 올린 파일을 `FS.writeFile` 로 넣고 pandas 로 읽는 길
- 나가는 요청을 세는 법, 그리고 **그 세기가 못 보는 것들**
- 한글 CSV 의 인코딩. `cp949` 파일을 `utf-8` 로 읽으면 무슨 오류가 나는지
- 고정폭 글꼴에 기대어 칸을 맞추면 안 되는 이유
- pandas 를 받는 비용과 큰 파일이 힙을 얼마나 먹는지

## 실행 방법

```bash
mise run serve
```

<http://localhost:4173/galleries/12-csv-analysis/> 를 연다. 파일이 없으면 "파일 없이 예제 데이터로" 를 누르면 된다.

## 핵심 코드

### 1. 나가는 요청을 세는 것은 쉽다

CSV 를 분석하는 웹 도구는 널려 있고 대부분 파일을 서버로 보낸다. 브라우저 파이썬이 다른 점은 계산이 사용자 기기 안에서 끝난다는 것인데, 개인정보가 든 파일을 올리라고 할 때 "안 보냅니다" 라는 문장 하나로는 부족하다.

브라우저가 이미 요청을 기록해 두므로 읽기만 하면 된다.

```js
// 이 문서가 만든 요청 전부. 브라우저가 기록해 둔 것을 그대로 읽는다.
function requests() {
  return performance.getEntriesByType('resource');
}
```

부팅이 끝난 시점의 개수를 기억해 두고, 그 뒤에 늘어난 것을 센다. 파일을 올리고 분석해도 이 숫자는 0 이다.

```text
부팅에 쓴 요청        17건 · 13.20 MiB 받음
분석하며 생긴 요청     0건
관측                 이 계측에 잡힌 요청은 없습니다
```

여기까지는 쉽다. 문제는 이 0 이 무엇을 뜻하느냐다.

### 2. 이 세기는 증명이 아니다

처음에는 이 자리에 "데이터는 이 브라우저를 벗어나지 않았습니다" 라고 적었다. 틀린 말이었다. 같은 페이지의 코드가 데이터를 보내도 이 숫자에 안 잡히는 길이 있다. 세 가지를 확인했다.

| 보내는 방법                     | Resource Timing 에 잡히나                      |
| ------------------------------- | ---------------------------------------------- |
| `fetch` 하고 응답 본문을 읽음   | 잡힌다                                         |
| **`fetch` 하고 응답을 안 읽음** | **안 잡힌다**                                  |
| **워커 안에서 보냄**            | **안 잡힌다** (워커는 자기 기록을 따로 갖는다) |
| `sendBeacon`                    | 잡힌다                                         |
| `new Image().src`               | 잡힌다                                         |
| **WebSocket**                   | **안 잡힌다** (애초에 기록 대상이 아니다)      |

두 번째가 특히 나쁘다. 데이터를 빼내는 코드는 응답이 필요 없으므로 오히려 이 모양이 기본형이다.

화면의 "일부러 몰래 보내 보기" 가 그걸 그대로 해 본다.

```js
// 응답을 읽지 않는 fetch 다. 보내는 쪽은 응답이 필요 없으니 유출 코드의 기본형이기도 하다.
// 같은 출처의 아무 주소나 두드린다. 서버가 뭘 돌려주든 상관없다.
fetch(`${location.pathname}?몰래=${encodeURIComponent('보낸 것처럼')}`, { method: 'POST' });
```

누르면 이렇게 나온다.

```text
응답을 읽지 않는 fetch 를 한 번 보냈습니다.
Resource Timing 이 센 요청: 17건 → 17건
늘지 않았습니다. 위의 표는 이 요청을 못 봅니다.
```

그래서 화면 문구를 "벗어나지 않았습니다" 에서 **"이 계측에 잡힌 요청은 없습니다"** 로 낮췄다. 관측한 것만 말하고 관측하지 않은 것을 단정하지 않는다.

정말 확인하려면 개발자 도구의 네트워크 탭을 열어 둔다. 위의 여섯 가지를 전부 잡는다. 이 예제가 알려 줄 수 있는 것은 "여기 이 코드에는 보내는 줄이 없다" 까지이고, 그것을 확인하는 자리는 소스와 네트워크 탭이다.

### 3. 기록은 지워질 수 있다

한 술 더 뜬다. Resource Timing 버퍼는 아무나 비울 수 있는 전역 상태다. `performance.clearResourceTimings()` 한 줄이면 이미 나간 요청의 기록도 사라진다.

그러면 "분석하며 생긴 요청" 이 다시 0 이 되어 판정이 조용히 뒤집힌다. 그래서 개수가 줄어든 것을 따로 잡는다.

```js
// 버퍼는 아무나 비울 수 있는 전역 상태다. 줄었다면 세던 근거가 사라진 것이다.
if (all.length < baseline) {
  addMetricRow(netRows, '분석하며 생긴 요청', '셀 수 없음');
  mark('계측을 믿을 수 없습니다. 기록이 지워졌습니다', false);
  return;
}
```

세던 근거가 사라졌으면 "없다" 가 아니라 "모른다" 라고 말해야 한다.

### 4. 파일은 가짜 파일시스템으로 들어간다

`<input type="file">` 로 고른 파일을 [08. 파일 다루기](../08-file-system/)에서 본 자리로 옮긴다.

```js
const bytes = new Uint8Array(await file.arrayBuffer());
pyodide.FS.writeFile(UPLOAD_PATH, bytes);
uploadedName = file.name;
// 값을 비워 둬야 같은 파일을 다시 골랐을 때도 change 가 뜬다.
fileInput.value = '';
await analyze('load_uploaded', encodingSelect.value);
```

마지막 줄이 없으면 같은 파일을 다시 골라도 아무 일이 안 일어난다. `<input type="file">` 은 값이 그대로면 `change` 를 내지 않는다.

파이썬 쪽은 그냥 경로를 읽는다. 이게 진짜 파일인지 메모리 위의 흉내인지 모른다. MEMFS 라 새로고침하면 사라진다.

### 5. 한글 CSV 는 대개 cp949 다

엑셀이 한글 윈도우에서 저장한 CSV 는 utf-8 이 아니다.

```python
try:
    frame = pd.read_csv(UPLOAD_PATH, encoding=encoding)
except UnicodeDecodeError as exc:
    # 한글 윈도우에서 만든 CSV 는 대개 cp949 다. 이 오류가 그 신호다.
    # from None 으로 pandas 안쪽 트레이스백을 끊는다. 안 끊으면 스무 줄이 먼저 나와서
    # 정작 무엇을 해야 하는지 적은 줄이 맨 아래로 밀린다.
    raise ValueError(
        f"{encoding} 로 읽지 못했습니다. 인코딩을 바꿔 보세요.\n원문: {exc}"
    ) from None
```

`from None` 이 중요하다. 안 끊으면 pandas 안쪽 트레이스백 스무 줄이 먼저 나오고, 정작 무엇을 해야 하는지 적은 줄이 맨 아래로 밀린다. 끊으면 화면에 이것만 남는다.

```text
ValueError: utf-8 로 읽지 못했습니다. 인코딩을 바꿔 보세요.
원문: 'utf-8' codec can't decode byte 0xc0 in position 0: invalid start byte
```

`0xc0` 은 utf-8 에서 시작 바이트로 쓸 수 없는 값이라 "position 0" 에서 바로 걸린다.

그리고 인코딩을 바꾸면 곧바로 다시 읽어야 한다.

```js
// 인코딩만 바꿔도 다시 읽어야 한다. 안 그러면 오류 화면을 띄워 놓고 고칠 길이 없다.
encodingSelect.addEventListener('change', () => {
  if (uploadedName) analyze('load_uploaded', encodingSelect.value);
});
```

이게 없으면 오류 화면을 띄워 놓고 고칠 길이 없다. 셀렉트를 바꿔도 아무 일이 안 일어나고, 같은 파일을 다시 골라도 `change` 가 안 뜬다.

### 6. 고정폭 글꼴을 믿고 칸을 맞추지 않는다

처음에는 열 목록을 파이썬에서 문자열로 만들어 `<pre>` 에 넣었다. 한글이 두 칸을 먹으니 `unicodedata.east_asian_width` 로 세어 채웠다. 그런데 화면에서 어긋났다.

재 보면 이유가 나온다.

```text
font=monospace  ascii=8.16px  한글=11.76px  배율=1.441
```

**브라우저의 고정폭 글꼴에서 한글은 두 칸이 아니라 1.44 칸이다.** `east_asian_width` 의 `W`/`F` 는 터미널의 약속이지 웹 폰트의 약속이 아니다. 한글 폰트가 따로 없어 대체 글꼴이 끼어들면 비율이 또 달라진다.

그래서 손으로 맞추기를 그만두고 표는 `<table>` 로 그린다. 파이썬은 값만 넘긴다.

pandas 가 만드는 `to_string()` 표도 같은 이유로 브라우저에서는 어긋난다. 이 예제는 그것을 그대로 두되 `<pre>` 안에 넣어 "이건 터미널용 서식" 이라는 것이 드러나게 했다.

## 직접 해볼 것

- 개발자 도구 네트워크 탭을 열어 두고 "일부러 몰래 보내 보기" 를 눌러 보자. 표는 0 건인데 네트워크 탭에는 찍힌다
- 콘솔에서 `performance.clearResourceTimings()` 를 부른 뒤 아무 버튼이나 눌러 보자. "계측을 믿을 수 없습니다" 로 바뀐다
- 한글이 든 CSV 를 엑셀에서 "CSV UTF-8" 이 아닌 그냥 "CSV" 로 저장해 올린 뒤, 인코딩 셀렉트만 `cp949` 로 바꿔 보자
- `src/main.js` 의 `fileInput.value = ''` 를 지우고 같은 파일을 두 번 골라 보자. 두 번째는 아무 일도 안 일어난다
- 10 MB 쯤 되는 CSV 를 올려 보자. 아래 표의 숫자를 직접 확인할 수 있다

## 막히는 지점

| 증상 | 원인 |
| --- | --- |
| `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc0` | 한글 윈도우에서 저장한 CSV 다. 인코딩을 `cp949` 로 바꾼다 |
| 요청 0 건인데 정말 안 나간 게 맞나 | 그 숫자는 관측이지 증명이 아니다. §2 참고 |
| 큰 파일을 올리면 잠깐 얼어붙는다 | 파싱이 메인 스레드에서 돈다. 10.9 MiB CSV 에서 434 ms 동안 화면이 멈췄다 |
| 큰 파일을 올리면 메모리가 확 는다 | 10.9 MiB CSV 를 읽자 WASM 힙이 74.9 MiB 에서 155.4 MiB 로 늘었다. 파일 크기의 7배쯤이다 |
| 작은 파일로 다시 읽어도 메모리가 안 줄어든다 | [05. 손잡이의 수명](../05-pyproxy-lifetime/)에서 본 그대로다. 힙은 늘기만 한다 |
| 새로고침하니 올린 파일이 없다 | MEMFS 다. 남기려면 IDBFS 를 쓴다 |
| 두 번째 방문에 받는 양이 확 줄어든다 | 캐시에서 온다. 13.20 MiB 가 23 KiB 로 나온 적도 있다 |
